This policy describes the private single-owner deployment. The tool is not a public hosted service and this page does not claim OAuth verification.

Purpose and Google permission

The helper uses Google Drive to reuse the owner's existing H3 cache and retain verified generation results. It requests only https://www.googleapis.com/auth/drive.file. This scope permits read and write access to files selected for the app and files it creates. The cache-transfer implementation reads the existing cache; backups may create or update app files. The permission is not read-only.

Data accessed or created

The selected existing cache consists of four model weight files, one prepared environment archive, and two verification receipts. File names, selected file identifiers, sizes, checksums, and receipt contents are used to validate that cache. Google account identity and storage quota may be checked to confirm the intended account and available storage.

A generation job processes its prompt and workflow settings and produces video and audio. Associated operational records may include job identifiers, timestamps, durations, SHA256 hashes, GPU and runtime observations, and compute usage records or estimates. An estimate is not a Google billing statement.

Where processing happens

For this deployment, processing involves Google services, the owner's host computer, and the Colab runtime the owner authorizes. The helper does not publish the model cache or generated media and does not send these files to advertising or third-party analytics services. It does not sell the owner's Google user data.

The owner controls the host and authorizes job execution. Google provides authorization, Drive storage, and Colab infrastructure under its own policies. Selected cache files are read directly into the runtime's temporary SSD, and results are returned to the host for verification and private backup.

Credentials and safeguards

OAuth refresh credentials remain on the owner's Linux host in an owner-only directory with mode 0700 and credential files with mode 0600. They are used to obtain short-lived access tokens. Refresh credentials and client configuration are not supplied to the Colab worker.

The worker receives a short-lived access token in a private, job-scoped file. Token values are excluded from public job envelopes and operational logs. Cleanup removes the temporary token file and releases the runtime; credential expiry, revocation, or a failed job can still require owner action. These safeguards are not a guarantee of permanent access or uninterrupted service.

Retention and deletion

Existing cache files and completed backups remain in the owner's Google Drive until the owner removes them. Host copies and operational records remain until the owner deletes them. Runtime SSD files are temporary and must not be treated as a durable backup; release of the runtime removes access to that temporary filesystem.

To end account access, revoke this app's grant through Google Account connections and delete the local OAuth credentials. Cancel or complete any active job and confirm its runtime is released. Stopping, uninstalling, or restoring the local helper does not automatically delete Google Drive files. Deleting credentials may require fresh authorization to use the helper again.

Questions and changes

Use the support contact shown on the Google authorization consent screen for questions about this private deployment. A material change in permissions, recipients, or purpose should be reviewed by the owner before use.
